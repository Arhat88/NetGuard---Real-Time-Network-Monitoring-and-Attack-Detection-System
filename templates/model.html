⊕ Model Overview
Random Forest · NSL-KDD · Multi-class Classification
This Intrusion Detection System (IDS) is built using a Random Forest Classifier, designed to identify and classify network traffic into normal or malicious categories. The system performs multi-class classification, detecting various types of attacks including DoS, Probe, R2L, and U2R along with normal traffic. It is trained on the NSL-KDD dataset, a refined version of the KDD'99 dataset, which eliminates redundancy and provides a more balanced benchmark for evaluating intrusion detection models. The primary goal of this model is to enable accurate and real-time detection of network threats in a simulated environment.
⚙ Techniques & Processing
Data pipeline · Feature engineering · Real-time inference
🔢
One-Hot Encoding
Categorical features such as protocol type, service, and flag are converted into numerical format using One-Hot Encoding, allowing the machine learning model to process them effectively without introducing ordinal bias.
⚖
SMOTE — Synthetic Minority Over-sampling
To address class imbalance in the dataset, especially for rare attack types like U2R and R2L, SMOTE is applied to generate synthetic samples, improving the model's ability to detect minority class attacks.
📡
Feature Extraction
The system extracts real-time network flow features such as count, same_srv_rate, dst_host_count, and packet statistics. These features help capture both short-term and host-level traffic behavior.
⚡
Real-Time Prediction & Logging
Captured network flows are processed in real-time, passed through the trained model for classification, and the results are logged into the system database for monitoring and analysis.

🗄 Dataset Details
NSL-KDD · 41 Features · Multi-class
The model is trained using the NSL-KDD dataset, which is widely used for evaluating intrusion detection systems. It contains a total of 41 features representing various aspects of network traffic.
FEATURE CATEGORIES
📦 Basic Features
Include fundamental connection attributes such as duration, protocol type, source bytes, and destination bytes.
📶 Traffic Features
Capture patterns within a time window, such as connection count and service-based statistics (e.g., count, same_srv_rate).
🖥 Host-based Features
Analyze connections to the same host over a longer duration, including features like dst_host_count and dst_host_srv_rate.
⚠ Class Imbalance: A key challenge in this dataset is class imbalance, where certain attack types like U2R (User to Root) and R2L (Remote to Local) have very few samples compared to others. This makes them harder to detect and necessitates the use of techniques like SMOTE.
